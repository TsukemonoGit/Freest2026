# 実装環境の選択肢：IDE比較

## MicroPython 用 IDE の選択肢

Pico 2 WH で MicroPython を使う場合の主な IDE は4つ。

### 1. Thonny

| 項目 | 内容 |
|------|------|
| 費用 | 無料（オープンソース） |
| 難易度 | 初心者向け |
| 対応OS | Windows / macOS / Linux |
| 特徴 | インストール1発でMicroPython環境が整う。REPL（対話式シェル）が内蔵。ファイル転送もGUIで可能 |
| メリット | 「迷わずに始められる」が最大の強み。設定がほぼ不要 |
| デメリット | 大規模プロジェクトには物足りない。Git統合がない |

### 2. VS Code + Raspberry Pi Pico 拡張（公式）

| 項目 | 内容 |
|------|------|
| 費用 | 無料（オープンソース） |
| 難易度 | 中級〜上級 |
| 対応OS | Windows / macOS / Linux |
| 特徴 | Raspberry Pi 公式の拡張機能。C/C++ SDK も MicroPython も両方対応 |
| メリット | Git統合、拡張機能、プロフェッショナルなワークフロー。AI補完も使える |
| デメリット | 初期セットアップに時間がかかる（初回はツールチェーンの自動インストールで5〜10分） |

### 3. Mu Editor

| 項目 | 内容 |
|------|------|
| 費用 | 無料（オープンソース） |
| 難易度 | 初心者向け |
| 対応OS | Windows / macOS / Linux |
| 特徴 | シンプルなエディタ。センサデータの可視化ツール（シリアルプロッタ）が内蔵 |
| メリット | UIがシンプル。センサ値をグラフで確認できる |
| デメリット | デバッガーがない。大規模プロジェクトには不向き |

### 4. Wokwi シミュレータ

| 項目 | 内容 |
|------|------|
| 費用 | 無料（ベーシック版）。プロ版あり |
| 難易度 | 全レベル |
| 対応OS | ブラウザのみ（Chrome / Firefox / Edge） |
| 特徴 | ブラウザ上で回路とコードをシミュレート。実機がいらない |
| メリット | 「.hw」を渡せば相手がすぐに動作を確認できる。リモート学習に最適 |
| デメリット | 実機の GPIO やPWM のタイミングとはずれることがある |

## 比較まとめ

| | Thonny | VS Code + 公式拡張 | Mu Editor | Wokwi |
|---|---|---|---|---|
| 費用 | 無料 | 無料 | 無料 | 無料（有料プランあり） |
| セットアップ難易度 | ★1（最易） | ★3（やや手間） | ★1（最易） | ★0（ブラウザだけでOK） |
| REPL | あり | あり（MicroPico経由） | あり | あり（シミュレータ内） |
| デバッガー | あり（ステップ実行） | あり（フル機能） | なし | ロジックアナライザ |
| Git統合 | なし | あり | なし | なし |
| センサ可視化 | なし | 拡張で可能 | あり（内蔵） | あり |
| 大規模プロジェクト | 不向き | 向いている | 不向き | 不向き |
| このプロジェクトに合うか | ○ 最初はこれ | ○ 後から切り替え可能 | △ デバッガーなし | △ シミュレータなので実機の結果とずれる |

## このプロジェクトでの推奨

**最初は Thonny、後から必要なら VS Code に切り替える。**

理由：
- 最初に大切なのは「すぐ動かして確認する」こと。Thonny はそのための最速の道。
- VS Code は機能が強いが、セットアップに時間がかかる。初心者が最初から使うと「環境構築でつまづく」リスクがある。
- 後から VS Code に切り替えるのは容易。コードはそのまま使える。

**ただし、VS Code を既に使い慣れている場合は最初から VS Code + 公式拡張でも問題ない。**
