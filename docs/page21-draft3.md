
# 21ページ目案：赤外線信号を解析する

## やりたいこと

「エアコンのリモコンは、エアコン本体にどのような信号を送っているのか？」

これを知ることで、Picoから赤外線を発してエアコンを操作できるようになる。
そのために、まずPicoで赤外線信号を受信し、記録し、比較する。
このページでは送信ではなく**観察と分析**に焦点を当てる。

---

## 準備：信号を受信するコード

赤外線受信モジュール（PL-IRM1838B）をPico 2 WHのGPIOに接続する。

### 最終的に得られるもの

リモコンのボタンを1回押すと、次のような**マイクロ秒単位の数値の並び**が画面に表示される。

```
エッジ数: 34
[560, 560, 560, 1690, 560, 560, ...]
```

この数値の並びが、その信号の正体。

### この出力の読み方

High／Lowの値そのものは記録していない。記録しているのは「切り替わった時刻」だけ。

赤外線信号はMARK（点滅）とSPACEが**交互に**現れるため、1番目・3番目…はMARK、2番目・4番目…はSPACE、と**順番だけで判別できる**。知りたいのは各区間の長さ（＝時刻の差）であり、それは「切り替わった瞬間」さえ記録できれば計算できる。

一定間隔で状態を確認し続ける方法（ポーリング）だと短い変化を見逃しやすいが、`irq`（割り込み）は変化の瞬間を自動で知らせてくれるため取りこぼしにくい。

### 処理の流れ（3段階）

| 段階 | やること |
|---|---|
| ① 待ち構える | 受信モジュールの出力が切り替わった瞬間だけを検知できるよう設定する |
| ② 記録する | その状態で2秒間待つ。この間にボタンを押すと、切り替わりのたびに時刻が自動で記録される |
| ③ 間隔を求める | 2秒経ったら記録を止め、記録された時刻どうしの差（間隔）を計算して表示する |

### 使う道具

- **`Pin`**：Picoの特定の端子（ピン）を、プログラムから操作できるようにする仕組み。`Pin(15, Pin.IN)`と書くと、「15番の端子を、信号を受け取る側（入力）として使う」という設定になる。
- **`ir.irq(...)`**：その端子に届く信号の変化を、自動的に検知する設定（①に対応）。`trigger`で「どんな変化を検知するか」、`handler`で「検知したら何を実行するか」を指定する。
    - `trigger`：`IRQ_FALLING`「電圧が下がった瞬間」、`IRQ_RISING`「電圧が上がった瞬間」
    - `handler`：`on_edge`関数で時刻を記録する
- **`ir.irq(handler=None)`**：検知の設定を解除する（③の直前に対応）。`handler`に「なし」を意味する`None`を渡すと、以降は電圧が変化しても何も呼び出されなくなる。以降の処理中に余計な信号を拾わないようにしている。

### コード

```python
from machine import Pin
import time

IR_PIN = 15
ir = Pin(IR_PIN, Pin.IN)

edges = []

def on_edge(pin):
    edges.append(time.ticks_us())

ir.irq(trigger=Pin.IRQ_FALLING | Pin.IRQ_RISING, handler=on_edge)

print("リモコンのボタンを1回だけ押してください")
edges.clear()
time.sleep(2)
ir.irq(handler=None)  # 記録を止める

# エッジ間隔（パルス幅）を計算
durations = []
for i in range(1, len(edges)):
    durations.append(time.ticks_diff(edges[i], edges[i - 1]))

print(f"エッジ数: {len(edges)}")
print(durations)
```

同じ手順で、複数のボタンについて信号を記録する。

- 暖房ON
- 除湿ON
- 停止
- 温度を1℃上げる
- 温度を1℃下げる
- 風量を変える

それぞれの`durations`をメモに控えておく。信号は長いため、全部を目で追う必要はない。まず**長さ（配列の要素数）**と**先頭付近の数値**を見比べる。

## 分析：パターンを比較する

多くのエアコンリモコンは、AEHAフォーマットと呼ばれる形式に準拠しているとされる（メーカーによって異なる可能性がある）。この形式では、先頭に長いヘッダパルスがあり、その後に信号の本体（データビット）が続く。

ビットへの変換は、スペース（パルスとパルスの間の無信号区間）の長さによって0か1かを判定する方法が使われることが多い。

記録した間隔の数値を1つずつ調べ、間隔がしきい値より長ければ1、短ければ0として、数値の並びを0と1の列に変換する。

```python
def durations_to_bits(durations, threshold=800):
    # threshold（しきい値）は実測して調整する
    # 一般に、短いスペースは0、長いスペースは1に対応するとされる
    bits = []
    for i in range(2, len(durations), 2):  # ヘッダ部を除き、スペース長のみを見る
        space = durations[i]
        bits.append(1 if space > threshold else 0)
    return bits

bits = durations_to_bits(durations)
print(bits)
```

「冷房ON」と「停止」で記録した`durations`をこの関数にかけ、出力されたビット列を並べて比べる。

## 「へー」となる

ビット列を並べて見ると、いくつかの規則性に気づくことがある。

- 全体の**先頭部分は毎回ほぼ同じ**（機種やメーカーを識別するための固定部分である可能性がある）
- **温度を変えたときだけ変化する箇所**がある（温度を表すビット群と推測できる）
- **風量を変えたときだけ変化する箇所**がある（温度の変化とは別の位置である可能性が高い）
- **冷房ON・暖房ON・除湿ONでそれぞれ異なる箇所**がある（運転モードを表すビット群と推測できる）
- **停止だけ、他のボタンと大きく異なる並び**になっている可能性がある（停止は運転モードとは別の、単独の指示として送られている可能性がある）

ここまでの作業で、「見た目は謎の数値の羅列」だった信号が、「温度・風量・運転モードなどの情報が、決まった位置のビットに対応している」という構造として見えてくる。
